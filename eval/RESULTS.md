# Evaluation: the pack against a model that watches video

Issue #2. Eight videos, 58 questions, three ways of answering them, run on
2026-11-27.

| Arm | How | Model |
|---|---|---|
| A | The whole video in one request through OpenRouter (`video_url`) | `google/gemini-3.8-flash` |
| B | A Havn agent with this pack (havn-watch, `view_image`, `transcribe`) | `deepseek/deepseek-v4.1-flash-1017` (images, no video) |
| C | The same as B | `google/gemini-3.8-flash`, so C against A is the pipeline's effect alone |

B and C ran on a Havn 0.2.16 build with `[transcription]` on
`google/gemini-3.8-flash`, `pids_max` 128 and `can_transcribe` on, each
video a new chat with the same prompt as A's.

## What went wrong in B and C

- **Text read from small frames.** Both agents tiled frames into small grids
  and read code and numbers from them. Text that small is unreadable, and
  both wrote down text that is not in the video (g4: a function
  `add_tax(cart, rate)` and `calculate_total(cart, tax_rate=0.05)` for
  `total_price(items, tax)`; g3: a slide title that does not exist) instead
  of saying they could not read it.
- **Frames that disappeared from the chat.** Havn showed a `view_image`
  image by reading its file again for every request, so once the agent
  removed its frame directory (as the skill said), every earlier view read
  "not shown: it is not there any more". B took this for failed views,
  threw away what it had seen and started again: on g3 it reached the
  100-tool-round limit with no answer. amplimit/Havn#354 fixes this.
- **A provider that drops images.** One of OpenRouter's providers for the
  deepseek model (OpenInference) takes the request and leaves the image out
  without an error; a request routed there is answered blind.
- **Refused requests.** C's r2 turn ended after 72 s without its answer.
  The gateway logged seven requests Gemini refused as unsafe (403) during
  the run; which turns they belonged to was not recorded.
- **Counting and timing were right when measured.** Both agents counted
  one-second events and timed changes exactly when they measured them with
  ffmpeg and pixel statistics rather than by looking at sampled frames.
- B searched the web once on r4, for the spelling of names it had heard.

The skill now says to read text only from one large frame and say when it
cannot, to measure counts and times, to stop well before the tool-round
limit, to remove its files in a step of its own, and when to tell the user
a model that watches video would do better. amplimit/Havn#355 brings arm
A's way into Havn: a video shown to a model that takes video.

## The videos

Generated by `make_videos.py`, with answers known by construction:

- **g1** (30 s): two spoken sentences, a code shown for 3 s, three
  background colours.
- **g2** (5 min): four spoken lines, three captions of 4 s, a square
  crossing three times, six red flashes of 1 s, five backgrounds.
- **g3** (20 min): twelve slides at irregular times, five spoken lines, a
  banner shown once for 3 s.
- **g4** (2 min): a code screencast: a function typed line by line, run,
  changed, run again, with narration.

The questions and references are in `questions.json`.

## Scoring

`grade.py` has `anthropic/claude-sonnet-5.5` score each answer against the
reference: 1, 0.5 (part of a several-part answer) or 0; a time within 2 s
(generated) or 3 s (real), a count exact, on-screen text word for word,
"cannot tell" 0. The scores of A and a sample of B's and C's were checked
by hand. Each run's answer, tool calls, time and cost are in `results/`,
the scores in `graded/`.

## Running it

- `make_videos.py DIR` makes the videos into `DIR`. It needs the pack's
  ffmpeg in `/opt/havn/ffmpeg` and `espeak-ng`.
- `native.py DIR results` runs arm A.
- `agent.py results B|C <agent-id>` runs an arm through a Havn gateway on
  `127.0.0.1:8080`. The agent has this pack and skill, and the videos in its
  workspace's `videos/`.
- `grade.py results` scores the runs and prints the table.

All of them read `OPENROUTER_API_KEY` from the environment.
